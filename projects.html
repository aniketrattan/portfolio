01 / Systems engineering2026 — Present

TupleStone
Embedded SQL

A compact C++20 embedded SQL database prototype with durable storage, typed values, transaction primitives, and a small relational front end.

  • Built checksummed page I/O, free-page reuse, buffering, heap, index, and WAL layers.
  • Added durable snapshot commits with restart replay and generation checks.
  • Exposed a small SQL evaluator and command-line shell with CMake/CTest builds.
Repository ↗

The question

What belongs in a small embedded database?

TupleStone explores the storage, recovery, and language boundaries that make a database useful inside an application without turning it into a server product.

The method

Build the layers from the page up.

The engine connects checksummed pages, a bounded buffer pool, heap and index primitives, a durable commit log, typed values, transactions, and a rule-based SQL evaluator through a strict CMake dependency graph.

The result

A working vertical slice with explicit boundaries.

The project is usable as a compact embedded engine while deeper page-backed integration, recovery coverage, relational operators, and sanitizer/fuzz suites remain clearly scoped.

02 / Developer tooling2026 — Present

DeliveryDrill
Webhook Testing

A Java 21 CLI for finding correctness bugs in webhook consumers when delivery is duplicated, delayed, reordered, malformed, or incorrectly signed.

  • Expressed delivery scenarios as readable YAML with deterministic seeds.
  • Exercised concurrent duplicates, retries, ordering faults, and HMAC verification.
  • Reported HTTP and state-invariant results in console, JSON, and JUnit XML formats.
Repository ↗

The question

Can a webhook consumer stay correct when delivery misbehaves?

Webhook systems retry, duplicate, delay, and reorder events. DeliveryDrill turns those failure modes into repeatable checks against a consumer you own.

The method

Make reliability failures deterministic.

Scenarios combine local JSON fixtures, named events, seeded fault injection, HMAC signing, HTTP assertions, and monotonic state invariants so a failing sequence can be reproduced locally or in CI.

The result

A focused feedback loop for webhook correctness.

The CLI keeps the testing boundary provider-neutral and produces machine-readable reports alongside concise console diagnoses.

At a glance

CIJSON / JUNIT REPORTS

A developer tool for testing the consumer, not operating another hosted webhook service.

03 / Data analysis07/2025 — 11/2025

Economic Growth &
Environmental Health

Analysed global panel data across approximately 190 countries to study the relationship between growth, PM2.5 pollution, and life expectancy.

  • Applied non-linear fixed-effects econometric models.
  • Identified Environmental Kuznets Curve turning points.
  • Developed forecasts for pollution decline during economic transitions.
Repository ↗

The question

Where does the relationship turn?

I analysed global panel data to study the relationship between economic growth, PM2.5 pollution, and life expectancy, looking for the point at which the environmental cost of growth begins to change direction.

The method

Model the shape, not just the average.

I applied non-linear fixed-effects econometric models with country and year effects and quadratic income terms to identify turning points and develop forecasts.

The result

A measurable turning point across a broad panel.

The analysis identified turning points in the income-pollution relationship and produced a way to discuss the direction of pollution after the peak rather than treating the trend as linear.
